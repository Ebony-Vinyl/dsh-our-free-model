# 插件升级导航页设计

## 目标

在插件管理界面的“网关设置”后增加“插件升级”导航项，让用户可以直接进入升级页面。现有升级能力已经实现，本次只调整入口和页面组织，避免用户在设置页中寻找升级功能。

## 范围

- 新增导航项 `插件升级`，位置紧跟 `网关设置`。
- 将现有升级面板独立渲染为插件升级页。
- 保留现有版本状态、检查更新、立即升级、热重载、恢复备份、升级历史和自动检查设置。
- 从原设置页移除重复的升级面板，确保功能只有一个入口。
- 中英文导航文本保持同步。

## 非目标

- 不修改升级下载、签名校验、备份恢复或热重载服务端逻辑。
- 不改变现有升级接口、权限校验和失败处理。
- 不调整其他模型、渠道、网关页面的业务行为。

## 交互与数据流

导航点击后更新当前页状态并渲染现有 `UpgradePanel`。页面通过已有管理 API 获取当前版本、磁盘版本、最新版本、检查时间和升级历史；检查更新与应用升级继续使用现有回调。升级完成后沿用当前事件通知和页面刷新逻辑。

如果运行版本与磁盘版本不一致、存在恢复状态或升级请求失败，继续显示现有提示和恢复入口，不新增旁路处理。

## 验收条件

1. 中文界面中“插件升级”出现在“网关设置”之后。
2. English 界面中对应显示 `Plugin upgrade`，位置一致。
3. 设置页不再重复渲染升级面板。
4. 升级页保留检查、应用、热重载、自动检查和恢复备份行为。
5. 现有升级相关测试、客户端静态检查和构建检查通过。
6. `git diff --check` 通过，且不包含用户已有的 README 或二维码改动。

## 风险与回退

本次只改变前端导航和组件挂载位置，风险集中在页面状态切换和测试选择器。回退时恢复原导航列表，并将 `UpgradePanel` 挂回设置页即可；升级服务端和用户升级数据不受影响。
