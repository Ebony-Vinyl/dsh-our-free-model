# 独立端模型清单改版

## 已确认的范围

用户已批准第二阶段计划并要求开始，先完成第一批模型清单。
沿用第一阶段公共导航、颜色和基础组件，将模型页面迁入 React。
保留名称与 ID 搜索、渠道筛选、模型能力和可用状态、复制 ID、
刷新清单、主动探测与单模型测试；补充能力和状态筛选及取消测试。
后续批次的用量、日志、设置、渠道详情、EAC 和登录改版分别推进。

## 页面与交互

页面采用便于扫描的模型列表，展示模型名称与 ID、渠道、视觉与思考能力、
上下文与输出上限、可用状态和操作。窄屏采用同一条目的紧凑布局。
长名称换行；完整 ID 可复制；未知容量和未探测状态明确显示。
清单收录和已探测可用分别显示，不将未接入渠道的模型标记为可调用。

搜索与筛选组合执行，并显示匹配数量与清单总数；无匹配时可清空筛选。
刷新状态不清空筛选，切页后返回保留筛选，退出会话后清空页面状态。
刷新清单与主动探测保留既有接口，主动探测仍明确标识会产生推理请求。
单模型测试一次仅运行一个；可取消；切页、退出及组件清理时中断测试。
测试结果区展示模型、耗时、正文或具体错误；旧请求不能覆盖新结果。

## 实现边界

- 模型页面按需加载，共用现有 React；概览启动时不渲染隐藏模型条目。
- 采用 TanStack Virtual 维护可见条目，支持动态高度、滚动与键盘聚焦，
  不手写虚拟列表引擎；筛选改变后回到列表开头。
- 使用现有管理会话、鉴权、超时与代际检查。扩展前端 Host 接口传递取消信号，
  后端沿用现有请求关闭后取消推理的机制。
- 移除旧模型 DOM 渲染与事件绑定，保留其余页面的控制逻辑。
- 不修改 DSH 插件、渠道协议、账号数据或推理核心，不迁移用户凭据。
- 分多个中文 commit；不提升版本、创建 tag、制作安装包或发布 Release。

## 验收

1. 类型检查、生产构建、生成一致性与管理鉴权专项通过。
2. 千模型数据只挂载可见条目；可滚动到末尾，筛选后不会停在空白位置。
3. 搜索名称和 ID、渠道/能力/状态组合筛选、无结果与重置正常。
4. 复制 ID、清单刷新、主动探测、测试成功/失败/取消均有明确反馈；
   切页和退出后迟到请求不恢复旧内容。
5. 桌面与窄屏实际点击、截图并检查溢出和浏览器错误。
6. 保留十三渠道与 EAC 页面可达，执行贡献者回归，记录静态资源体积。
7. 计时注明测量方法与样本，不将工具往返时间当作纯渲染耗时。

## 实施任务

1. 同步主线、记录设计与基线，安装虚拟列表依赖。
2. 迁移模型页面与承载接口，完成取消和异步生命周期处理。
3. 实现列表布局、虚拟滚动、筛选与测试状态。
4. 构建、专项及浏览器验收，修复实际发现的问题。
5. 记录证据与限制，分批提交代码、测试及文档。
