# Our Free Model 2.5.1

## 本次更新

- **修复升级失败：新增国内可达的清单镜像源。** 部分网络下 `raw.githubusercontent.com`
  与 `cdn.jsdelivr.net` 很慢或间歇性不可达（实测 `raw` 单次要 16.6 秒，常撞上 15 秒
  预算而超时；jsDelivr 约 11 秒且偶发断流），导致「检查更新」直接报
  `no manifest source answered`。现在两条链路都新增一个
  `raw.githubusercontent.com` 代理镜像（实测约 1.3 秒返回同样字节）：
  - 升级清单：`raw` → `cdn.jsdelivr` → **镜像** → `master` 兜底；
  - 公告订阅：同样加入镜像，保证开屏公告在慢网络下也能拉到。
  - 镜像**不是**从可变分支取件：它和直连源一样先解析成完整 commit SHA，再按
    SHA 取清单与每个文件；签名与逐文件 SHA-256 校验照常执行，镜像本身不被信任。
    新增的 `updater-test` 断言把镜像源纳入「固定到 commit SHA、禁止分支安装」这组
    检查。
- **修复 EAC 卡片小字显示 `org/` 前缀。** EAC 行的 `id` 保留 `org/` 前缀是必需的——
  免费车道有同名模型（裸名 `deepseek-v4.1-flash-free`），合并时按 id 去重，前缀正是
  让 EAC 那一行不被免费车道顶掉的原因；但前缀只是路由细节，不该出现在卡片上。现在
  卡片小字显示模型自己的 id（`deepseek-v4.1-flash-free`），名称行仍显示
  `EAC DeepSeek V4.1 Flash Free`。
- 服务端 EAC 渠道的对外模型名改回 `opencode/...` 前缀（并用渠道映射指回上游裸名），
  于是插件的置顶、`NEW` / `爆` 徽标、`高速` 标签、1M 上下文与思考档位全部生效。

## 升级与重启

### DSH 插件

在设置 → 插件升级中检查并安装 2.5.1。若当前网络下 `raw.githubusercontent.com` 与
`cdn.jsdelivr.net` 均不可达，本次加入的镜像源会在同一次检查里接管，无需额外配置。

### 独立本地服务 / Windows 桌面应用

与 2.5.0 的说明一致：先退出托盘程序，再用原来的数据目录启动新版或安装新版完整安装包。

## 数据与回退

升级保留现有配置、账号和统计数据。回退到 2.5.0 不影响用户数据；旧版本在慢网络下会
重新遇到「检查更新失败」，属预期。
